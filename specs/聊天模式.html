1. 概述

現況

目前系統支援：

  • 單一代理者與使用者對話
  • 每個代理者獨立運作，擁有各自的 system_prompt、MCP、Skills、RAG
  • is_router 欄位存在但尚未啟用協調功能

目標

實現多代理者協作，讓代理者能夠：

  1. 討論 - 針對任務互相交換意見
  2. 規劃 - 共同研究出執行計畫
  3. 分工 - 根據各自專長分配子任務
  4. 彙整 - 將各代理者的成果整合回報

2. 模式 A：Router 協調模式

概念

由一個「主代理者（Router）」擔任指揮官角色，負責：

  • 分析使用者任務
  • 決定需要哪些子代理者參與
  • 發送子任務給各代理者
  • 彙整所有回覆後回報使用者

架構圖

┌─────────────────────────────────────────────────────────────┐ │ 使用者 │ └─────────────────────────────┬───────────────────────────────┘ │ 提問/任務 ▼ ┌─────────────────────────────────────────────────────────────┐ │ Router Agent (主代理者) │ │ ┌─────────────────────────────────────────────────────┐ │ │ │ 1. 分析任務 │ │ │ │ 2. 決定參與的子代理者 │ │ │ │ 3. 生成子任務 prompt │ │ │ │ 4. 彙整結果 │ │ │ └─────────────────────────────────────────────────────┘ │ └───────┬─────────────────┬─────────────────┬─────────────────┘ │ │ │ ▼ ▼ ▼ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ │ Agent A │ │ Agent B │ │ Agent C │ │ (程式專家) │ │ (測試專家) │ │ (文件專家) │ └───────┬───────┘ └───────┬───────┘ └───────┬───────┘ │ │ │ └────────────────┬┴─────────────────┘ │ 各自回覆 ▼ ┌─────────────────────────────────────────────────────────────┐ │ Router Agent (彙整) │ └─────────────────────────────┬───────────────────────────────┘ │ 最終回覆 ▼ ┌─────────────────────────────────────────────────────────────┐ │ 使用者 │ └─────────────────────────────────────────────────────────────┘

執行流程（虛擬碼）

async def router_handle_message(user_message: str):
    # Step 1: 分析任務，決定需要哪些代理者
    analysis = await router_llm.analyze(f"""
        使用者任務: {user_message}
        可用代理者: {available_agents}
        請決定需要哪些代理者參與，以及各自的子任務。
    """)

    # Step 2: 並行呼叫子代理者
    sub_tasks = analysis.sub_tasks
    results = await asyncio.gather(*[
        call_sub_agent(task["agent_id"], task["prompt"])
        for task in sub_tasks
    ])

    # Step 3: 彙整結果
    final_response = await router_llm.synthesize(f"""
        原始任務: {user_message}
        各代理者回覆: {format_results(results)}
        請彙整成完整回覆。
    """)

    return final_response

Router 設定

{
  "is_router": true,
  "router_config": {
    "mode": "parallel",           // parallel | sequential | adaptive
    "max_sub_agents": 5,          // 最多同時呼叫幾個代理者
    "timeout_per_agent_ms": 30000,
    "fallback_on_error": true,    // 子代理者失敗時是否繼續
    "sub_agent_ids": ["uuid1", "uuid2", "uuid3"],
    "routing_prompt": "..."       // 自訂路由決策 prompt
  }
}

優點

  • 架構清晰，易於理解
  • 使用者只需與一個入口互動
  • 子代理者可以並行執行，效率高
  • Router 可以過濾/重組子代理者的回覆

缺點

  • Router 成為單點瓶頸
  • 子代理者間無法直接對話
  • Router 的 prompt 設計複雜度高
  • 需要額外的 token 消耗（Router 分析 + 彙整）

3. 模式 B：對話鏈模式

概念

代理者之間可以互相「@mention」進行對話，形成討論鏈。類似 Slack/Discord 的體驗。

架構圖

┌─────────────────────────────────────────────────────────────┐ │ 共享對話空間 │ ├─────────────────────────────────────────────────────────────┤ │ │ │ [使用者] 請幫我設計一個登入系統 │ │ │ │ │ ▼ │ │ [Agent A - 架構師] │ │ 我建議使用 JWT + OAuth2，@Agent_B 你覺得安全性如何？ │ │ │ │ │ ▼ │ │ [Agent B - 資安專家] │ │ JWT 需要注意 token 過期和刷新機制。建議加上 refresh token。 │ │ @Agent_C 請根據這個方向實作。 │ │ │ │ │ ▼ │ │ [Agent C - 開發者] │ │ 好的，我開始實作。以下是程式碼： │ │ ```python │ │ class AuthService: │ │ ... │ │ ``` │ │ │ │ │ ▼ │ │ [Agent A - 架構師] │ │ 程式碼看起來不錯。@使用者 以上是我們團隊的討論結果。 │ │ │ └─────────────────────────────────────────────────────────────┘

執行流程（虛擬碼）

async def handle_message_chain(conversation_id: str, sender: str, message: str):
    # Step 1: 解析 @mention
    mentions = parse_mentions(message)  # ["Agent_B", "Agent_C"]

    # Step 2: 儲存訊息到共享對話
    await save_message(conversation_id, sender, message)

    # Step 3: 通知被 mention 的代理者
    for mentioned_agent in mentions:
        context = await get_conversation_context(conversation_id)
        response = await agent_respond(
            agent_id=mentioned_agent,
            context=context,
            trigger_message=message
        )
        # 遞迴處理（可能包含新的 @mention）
        await handle_message_chain(conversation_id, mentioned_agent, response)

@mention 語法

語法說明
@Agent_Name指定代理者
@all所有代理者
@team:dev標籤為 "dev" 的代理者群組
@user回覆使用者

對話鏈設定

{
  "chain_config": {
    "max_chain_depth": 10,        // 最大對話深度，防止無限迴圈
    "max_agents_per_turn": 3,     // 每輪最多觸發幾個代理者
    "require_user_approval": false,
    "auto_conclude_after": 5,     // 幾輪後自動總結
    "allowed_mention_agents": ["uuid1", "uuid2"]
  }
}

優點

  • 對話自然，類似人類團隊討論
  • 代理者可以互相補充、質疑、改進
  • 適合需要多輪討論的複雜任務
  • 使用者可以觀察整個討論過程

缺點

  • 可能產生過多對話（token 消耗高）
  • 需要防止無限迴圈（A → B → A → B...）
  • 對話順序管理複雜
  • 延遲可能較高（需要等待每個代理者回覆）

4. 模式 C：共享記憶體模式

概念

所有代理者共享一個「任務板（Task Board）」或「知識庫」，各自讀寫資訊。類似 Notion/Trello 協作。

架構圖

┌─────────────────────────────────────────────────────────────┐ │ 共享任務板 (Task Board) │ ├─────────────────────────────────────────────────────────────┤ │ │ │ ┌─────────────────────────────────────────────────────┐ │ │ │ 任務：設計登入系統 │ │ │ │ 狀態：進行中 │ │ │ └─────────────────────────────────────────────────────┘ │ │ │ │ ┌─ 分析區 ─────────────────────────────────────────────┐ │ │ │ [Agent A] 需求分析： │ │ │ │ • 需要支援 OAuth2 │ │ │ │ • 需要 MFA 支援 │ │ │ └─────────────────────────────────────────────────────┘ │ │ │ │ ┌─ 設計區 ─────────────────────────────────────────────┐ │ │ │ [Agent B] 技術設計： │ │ │ │ • 架構圖：[連結] │ │ │ │ • API 規格：[連結] │ │ │ └─────────────────────────────────────────────────────┘ │ │ │ │ ┌─ 實作區 ─────────────────────────────────────────────┐ │ │ │ [Agent C] 程式碼： │ │ │ │ • auth_service.py ✅ │ │ │ │ • token_manager.py ✅ │ │ │ │ • tests/ 🔄 進行中 │ │ │ └─────────────────────────────────────────────────────┘ │ │ │ └─────────────────────────────────────────────────────────────┘ ▲ ▲ ▲ ▲ │ │ │ │ ┌────┴────┐ ┌────┴────┐ ┌────┴────┐ ┌────┴────┐ │ Agent A │ │ Agent B │ │ Agent C │ │ Agent D │ │ (分析) │ │ (設計) │ │ (實作) │ │ (審查) │ └─────────┘ └─────────┘ └─────────┘ └─────────┘

任務板結構

{
  "task_id": "uuid",
  "title": "設計登入系統",
  "status": "in_progress",
  "participants": [
    {"agent_id": "uuid1", "role": "analyst"},
    {"agent_id": "uuid2", "role": "designer"},
    {"agent_id": "uuid3", "role": "developer"},
    {"agent_id": "uuid4", "role": "reviewer"}
  ],
  "sections": {
    "requirements": [...],
    "design": [...],
    "implementation": [...],
    "review": [...]
  },
  "workflow": {
    "stages": ["requirements", "design", "implementation", "review"],
    "current_stage": "implementation",
    "stage_dependencies": {
      "design": ["requirements"],
      "implementation": ["design"],
      "review": ["implementation"]
    }
  }
}

優點

  • 結構化，易於追蹤進度
  • 各代理者可以非同步工作
  • 支援複雜的工作流程（依賴關係）
  • 所有資訊集中，便於回顧

缺點

  • 需要額外的「任務板」資料結構
  • 代理者需要理解任務板操作
  • 即時性較差（輪詢 vs 推送）
  • 衝突處理（多代理者同時寫入）

6. 資料模型擴充

Agent 模型擴充

class Agent(Base):
    # ... 現有欄位 ...

    # 新增欄位
    is_router = Column(Boolean, default=False)  # 已存在
    router_config = Column(JSON, default=dict)  # Router 設定

    # 代理者角色/專長標籤
    tags = Column(JSON, default=list)  # ["developer", "security", "docs"]

    # 可被哪些代理者呼叫
    callable_by = Column(JSON, default=list)  # ["*"] 或 ["uuid1", "uuid2"]

新增：多代理者對話模型

class MultiAgentConversation(Base):
    """多代理者協作對話"""
    __tablename__ = 'multi_agent_conversations'

    id = Column(GUID(), primary_key=True, default=uuid.uuid4)
    title = Column(String(200))
    mode = Column(String(20))  # router | chain | board
    status = Column(String(20))  # active | completed | failed

    # 參與者
    initiator_user_id = Column(GUID(), ForeignKey('users.id'))
    router_agent_id = Column(GUID(), ForeignKey('agents.id'), nullable=True)
    participant_agent_ids = Column(JSON, default=list)

    # 設定
    config = Column(JSON, default=dict)

    created_at = Column(DateTime, default=datetime.utcnow)
    updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)


class MultiAgentMessage(Base):
    """多代理者對話訊息"""
    __tablename__ = 'multi_agent_messages'

    id = Column(GUID(), primary_key=True, default=uuid.uuid4)
    conversation_id = Column(GUID(), ForeignKey('multi_agent_conversations.id'))

    # 發送者（可以是使用者或代理者）
    sender_type = Column(String(10))  # user | agent
    sender_id = Column(GUID())  # user_id 或 agent_id

    # 訊息內容
    content = Column(Text)
    mentions = Column(JSON, default=list)

    # 元資料
    parent_message_id = Column(GUID(), nullable=True)
    metadata = Column(JSON, default=dict)

    created_at = Column(DateTime, default=datetime.utcnow)


class TaskBoard(Base):
    """共享任務板"""
    __tablename__ = 'task_boards'

    id = Column(GUID(), primary_key=True, default=uuid.uuid4)
    conversation_id = Column(GUID(), ForeignKey('multi_agent_conversations.id'))

    title = Column(String(200))
    status = Column(String(20))  # pending | in_progress | completed

    # 工作流程
    workflow = Column(JSON, default=dict)
    current_stage = Column(String(50))

    # 各區塊內容
    sections = Column(JSON, default=dict)

    created_at = Column(DateTime, default=datetime.utcnow)
    updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)

7. API 設計

Router 協調模式 API

POST /multi-agent/router/chat
{
  "router_agent_id": "uuid",
  "message": "請幫我設計登入系統",
  "config": {
    "max_sub_agents": 3,
    "timeout_ms": 60000
  }
}

Response (SSE stream):
event: router_thinking
data: {"status": "analyzing", "message": "分析任務中..."}

event: sub_agent_start
data: {"agent_id": "uuid1", "agent_name": "架構師", "task": "設計系統架構"}

event: sub_agent_response
data: {"agent_id": "uuid1", "content": "建議使用..."}

event: final_response
data: {"content": "根據團隊討論，我們建議..."}

對話鏈模式 API

POST /multi-agent/chain/message
{
  "conversation_id": "uuid",
  "sender_type": "user",

  "config": {

data: {"message_id": "uuid2", "agent_name": "架構師", "content": "我建議...@資安專家"}
