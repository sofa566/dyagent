# 007-llm-cost 變更計畫（LLM Token/Cost 四層治理）

## 目標

建立以 `llm_turns` 為唯一資料來源的 LLM 成本治理能力，提供以下四層可視化與控管：

- 公司（Company）
- 群組（Group）
- 個人（User）
- 代理者（Agent）

同時支援：

1. 成本與 token 報表查詢（管理者視角）
2. 個人用量查詢（使用者視角）
3. 預算政策管理（先告警、後阻擋）

---

## 核心原則

1. 以每次實際 LLM 呼叫落地的 `llm_turns.usage` 為 token 基礎。
2. 成本優先採用供應商直接回傳值，缺值時才用單價表估算。
3. 先提供可見與告警，不直接啟用硬阻擋，降低誤殺風險。
4. 四層口徑一致，避免不同頁面與 API 定義不一致。

---

## 分階段

### 階段 1：四層報表能力

- 新增四層聚合 API（公司/群組/個人/代理者）
- 儀表板顯示四層成本與 token 指標
- 明確回傳 `input_tokens`、`output_tokens`、`total_tokens`

### 階段 2：預算政策與告警

- 新增四層預算設定（token 與 USD）
- 產出 50% / 80% / 100% 告警事件
- 支援「告警模式（warn-only）」

### 階段 3：阻擋治理

- 啟用可切換 hard-limit 模式
- 四層任一超限即拒絕
- 回傳一致的拒絕原因碼，供前端與稽核顯示

---

## 驗收重點

1. 四層同時間窗下數據可追溯且可對帳。
2. 管理者可從儀表板快速定位高成本來源（群組/個人/代理者）。
3. 告警與拒絕行為可在稽核記錄中完整追蹤。
