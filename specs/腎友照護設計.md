# 腎友照護 POC 設計說明

## 1. 文件目的

本文件定義腎友照護 POC 在 dyagent 上的實作架構、模組邊界與 UI 對齊規範。參考來源包含：

- `specs/腎友照護POC工程交付規格書_v1.0.docx`
- 端到端流程圖（A 非透析日、B 透析日）
- 展示站 `https://renal-care-poc.superlee84248.chatgpt.site/`

本階段先完成「可展示的最小閉環」，不在此階段處理院內正式介接、法規認證與醫囑自動化。

---

## 2. 核心設計原則

1. 分層清楚：LINE 對話、照護工作台、技能管理三層分離。
2. AI 只整理與提醒：不做診斷、不下醫囑、不自動結案。
3. 人工確認優先：所有醫療處置節點保留護理師確認。
4. 全程可追溯：每筆輸入、規則比對與提醒皆有紀錄。
5. 先閉環再擴展：先做四位虛構病患 POC，再談通用化。

---

## 3. 架構總覽

### 3.1 邏輯分層

1. 任務入口與路由層（Router）
   - 接收排程事件、LINE 訊息、護理師操作。
   - 將任務分類為：
     - A：日常監測（非透析日）
     - B：透析療程（透析日）

2. 業務技能層（Skills）
   - S01：腎友日常監測 Skill
   - S02：透析療程紀錄與提醒 Skill
   - 僅負責驗證、儲存、規則比對、輸出提醒與追蹤建議。

3. 通道與操作層（Channel + Console）
   - LINE 通道：病患、家屬、照護者逐項填報入口。
   - 護理工作台：四人總覽、異常追蹤、人工接手、結案確認。

4. 資料與稽核層
   - 病患、療程、監測、追蹤、事件、訊息紀錄。
   - 需可查詢「何人、何時、做了什麼、依據哪條規則」。

### 3.2 模組責任邊界

- dyagent 平台：對話、任務路由、工具執行、權限與審計框架。
- 腎友照護場景模組：透析業務欄位、追蹤規則、四人看板。
- LINE OA：外部通道，負責使用者觸達，不承擔醫療判斷。

---

## 4. 端到端流程設計

### 4.1 A 流程：非透析日日常監測

1. 洗腎 Agent 建立填報任務（06:00、21:00，或不舒服主動填寫）。
2. LINE 逐項詢問（體重、血壓、脈搏；糖尿病加血糖與傷口）。
3. 使用者確認後送出。
4. 呼叫 S01 寫入與比對個別標準。
5. 判斷是否需追蹤：
   - 否：更新 Dashboard
   - 是：建立主護追蹤任務並通知

### 4.2 B 流程：透析日療程紀錄

1. 洗腎 Agent 建立透析任務（依班別）。
2. 護理師確認病患、班別、床號、機號。
3. 護理師確認洗前體重與目標脫水量。
4. 呼叫 S02 持續寫入透析中資料與事件。
5. 判斷是否發生異常：
   - 否：洗後確認完成
   - 是：護理師現場處理，記錄暫停/恢復/提前結束

### 4.3 安全邊界

- AI 僅做比對與提醒，不做處置決策。
- 所有異常處理與結案均需人工確認。

## 5. UI/UX 設計對齊規範（需與參考站一致）

### 5.1 畫面資訊架構

1. 首頁為「腎友照護 POC 工作台」，上方提供角色切換按鍵：
   - 護理師
   - 腎友／家屬
2. 上方摘要列：
   - 床機配對
   - 正常完成
   - 需要追蹤
   - 目標脫水完成率
3. 主內容分頁：
   - 四人總覽
   - AI 智慧照護
   - 今日透析
   - 個案趨勢
    - LINE 對話
    - 異常追蹤

### 5.5 角色切換與雙工作台

參考站上方角色切換不是單純樣式切換，而是兩個不同操作情境。POC 需明確規劃兩套畫面：

1. 護理師工作台（Nurse Workspace）
   - 目標：同時管理多位病患與透析流程。
   - 主要內容：六項左側 Menu、異常追蹤、人工確認與結案。

2. 腎友／家屬工作台（Patient/Family Workspace）
   - 目標：單一病患視角，完成填報、查看趨勢與衛教。
   - 主要內容：
     - 今日填報任務（早/晚）
     - 最近量測摘要
     - 個人趨勢與提醒
     - LINE 對話入口與填報歷程

3. 導航與登入規則
   - 角色按鍵切換後，進入對應工作台路由，不共用同一主內容容器。
   - 護理師與腎友／家屬使用不同的權限範圍與資料可視範圍。
   - 腎友／家屬僅可看到自己的資料，不可見其他病患。

### 5.4 左側 Menu 對齊（六項）

依參考站實際左側選單，POC 需對齊六個項目與對應畫面：

1. 四人總覽
   - 顯示四位病患卡片、床機配對、當班狀態與追蹤標記。
2. AI 智慧照護
   - 顯示 AI 產生的照護摘要、提醒與後續建議（僅提示，不含醫囑）。
3. 今日透析
   - 顯示當班透析任務、洗前確認、透析中事件與洗後完成狀態。
4. 個案趨勢
   - 顯示近七日體重、血壓、脫水進度與異常次數趨勢。
5. LINE 對話
   - 進入 LINE 對話中心，支援 bot/human 模式與人工回覆。
6. 異常追蹤
   - 顯示需主護追蹤案件、處理進度、結案狀態與責任人。

### 5.2 視覺語言（對齊參考站）

- 主色：深藍 + 醫療綠作為狀態與區塊主色。
- 卡片：白底、圓角、中等陰影、清晰邊框。
- 標籤語意：
  - 正常/完成：綠色
  - 追蹤/警示：橘色
  - 異常/緊急：紅色
- 字體與層級：
  - 標題粗體、數值高對比、說明文字次要色

### 5.3 互動一致性

- 所有確認節點需二次確認或明確按鈕文案。
- 所有狀態切換（bot/human、追蹤中/已完成）需有即時回饋。
- 病患卡片操作入口一致：趨勢、療程紀錄、追蹤詳情。

## 6. 頁面與功能分工（最佳作法）

1. 護理師工作台（新增）
   - 功能：四人總覽、AI 智慧照護、今日透析、個案趨勢、LINE 對話、異常追蹤。
   - 定位：多病患營運與醫護操作主畫面。

2. 腎友／家屬工作台（新增）
   - 功能：個人填報任務、個人趨勢、提醒與衛教、與照護團隊訊息互動。
   - 定位：單一病患自助與回報主畫面。

3. LINE 對話中心（既有）
   - 功能：會話檢視、bot/human 切換、人工回覆。
   - 定位：通道操作台。

4. Skills 管理頁（既有）
   - 功能：S01/S02 啟用、版本、測試與配置。
   - 定位：系統配置台。

> 不將完整照護操作塞入 Skills 頁。Skills 頁只做管理，不做即時照護作業。

---

## 7. API 與 Skill 對應（POC 範圍）

### 7.1 S01 對應

- `POST /api/monitoring-records`
  - 早晚量測/症狀填報寫入
  - 比對個別標準
  - 回傳是否需追蹤與病患訊息

### 7.2 S02 對應

- `POST /api/dialysis-sessions`：建立透析 Session
- `POST /api/dialysis-events`：透析中事件寫入
- `POST /api/dialysis-post-check`：洗後確認與完成

### 7.3 工作台查詢

- `GET /api/dashboard/renal/summary`：四人摘要
- `GET /api/dashboard/renal/patients`：病患卡片與當班狀態
- `GET /api/dashboard/renal/follow-ups`：異常追蹤列表

## 8. 實作階段規劃

### Phase 1：資料模型與 API 骨架

- 建立病患、監測紀錄、透析 session、透析事件、追蹤任務模型。
- 建立 S01/S02 API 骨架與驗證。

### Phase 2：LINE + Skill 閉環

- 將 LINE 填報導入 S01。
- 透析流程操作導入 S02。

### Phase 3：Dashboard（對齊參考站）

- 完成四人總覽、狀態卡、追蹤面板與個案詳情。
- 視覺與互動對齊展示站語言。

### Phase 4：驗收與演示腳本

- 十項驗收案例逐項驗證。
- 產出 demo 路徑：非透析日、透析日、異常處理、人工接手。

---

## 9. 驗收準則（POC）

1. 兩個 Skill 可被實際呼叫，資料可寫入且可查。
2. LINE 可完成填報與人工接手回覆。
3. Dashboard 可呈現四位病患的即時狀態與追蹤。
4. 任何異常都需有人員確認紀錄，無自動醫療處置。
5. UI 視覺層級、資訊分區與操作節奏與參考站一致。

---

## 10. 雙角色頁面地圖與路由命名建議

### 10.1 路由總覽

1. 護理師工作台根路由：`/pages/renal-care-nurse.html`
2. 腎友／家屬工作台根路由：`/pages/renal-care-patient.html`
3. LINE 對話中心：`/pages/line-console.html`
4. Skills 管理：沿用既有 `skills` 系列頁面

### 10.2 護理師工作台分頁（左側 Menu 六項）

建議以 query 參數切頁，避免 POC 初期建立過多檔案：

- `?tab=overview`：四人總覽
- `?tab=ai-care`：AI 智慧照護
- `?tab=today-dialysis`：今日透析
- `?tab=trends`：個案趨勢
- `?tab=line`：LINE 對話（可導向 `line-console`）
- `?tab=alerts`：異常追蹤

完整範例：

- `/pages/renal-care-nurse.html?tab=overview`
- `/pages/renal-care-nurse.html?tab=alerts`

### 10.3 腎友／家屬工作台分頁

同樣採 query 參數分頁：

- `?tab=tasks`：今日填報任務
- `?tab=summary`：最近量測摘要
- `?tab=trend`：個人趨勢
- `?tab=education`：個人化衛教
- `?tab=messages`：LINE 對話與回覆歷程

完整範例：

- `/pages/renal-care-patient.html?tab=tasks`
- `/pages/renal-care-patient.html?tab=trend`

### 10.4 角色切換導覽規則

1. 點「護理師」：固定導向 `/pages/renal-care-nurse.html`。
2. 點「腎友／家屬」：固定導向 `/pages/renal-care-patient.html`。
3. 兩邊皆保留目前 tab 狀態；若目標角色無對應 tab，回退到預設 tab。

### 10.5 權限與資料可視範圍

1. 護理師工作台：可查看四位病患與追蹤案件。
2. 腎友／家屬工作台：僅可查看自身病患資料。
3. LINE 對話人工回覆、模式切換：僅護理師/管理角色可操作。

### 10.6 前端檔案命名建議

1. `frontend/src/pages/renal-care-nurse.html`
2. `frontend/src/pages/renal-care-patient.html`
3. `frontend/src/pages/renal-care-components.js`（共用渲染函式）
4. `frontend/src/pages/renal-care-api.js`（共用 API 呼叫）

> POC 原則：先頁面可用與流程可驗收，再逐步抽共用元件與樣式系統。
