# 上線前缺口清單（P0 / P1 / P2）

本清單以目前系統能力（MCP、Skill、RAG、Memory）為基礎，整理可執行的上線前補強項目。

## P0（上線前必做）

### 1. Secrets 與憑證治理
- 目標：避免 API Key / Token 外洩與誤提交。
- 工作項目：
  - 全部 API Key 改用環境注入，不放入版本庫。
  - 建立 `.env` 掃描規則（pre-commit + CI）。
  - 建立金鑰輪替 SOP（包含緊急撤銷流程）。
- 驗收標準：
  - repo 掃描無明文憑證。
  - CI 會阻擋可疑 key 字串。

### 2. 觀測性基礎（可追蹤）
- 目標：每次請求可追到路由、工具、RAG、記憶寫入與錯誤。
- 工作項目：
  - 統一 request_id / conversation_id / user_id / agent_id 日誌欄位。
  - 指標化成功率、延遲、錯誤碼（memory/mcp/rag）。
  - 保留關鍵事件：`route.decision`、`memory.write`、`tool_result`。
- 驗收標準：
  - 任一失敗案例可在 5 分鐘內定位到子系統層級。

### 3. 降級矩陣與故障保護
- 目標：單點故障時仍可提供可預期回覆。
- 工作項目：
  - 定義 LLM、Qdrant、Redis、MCP 各自故障時降級策略。
  - 明確 fail-open / fail-close 規則與回應文案。
  - 加入 timeout、retry、circuit breaker 門檻。
- 驗收標準：
  - 壓測注入故障時，API 不會大量 500，且回應符合降級規範。

### 4. 安全邊界（Prompt Injection / Tool Guard）
- 目標：避免外部輸入驅動危險工具行為。
- 工作項目：
  - 工具白名單與參數驗證（含最大長度/格式）。
  - 外部內容（RAG/MCP）標示為不可信上下文。
  - 高風險操作需二次確認或管理者權限。
- 驗收標準：
  - 針對 injection 測試集，敏感工具無未授權觸發。

## P1（上線後 1~2 週內）

### 5. 評測與回歸管線（品質可比較）
- 目標：每次改版可量化「變好或變差」。
- 工作項目：
  - 建立固定測試題庫（一般問答、工具調用、RAG、記憶）。
  - 產出指標：答覆正確率、工具成功率、RAG 命中率、幻覺率。
  - 將 `specs/pr_mem_test.sh` 納入回歸流程。
- 驗收標準：
  - 每次 release 皆有對照報告（與上一版比較）。

### 6. RAG 與 Memory 資料生命週期
- 目標：資料可追溯、可更新、可刪除。
- 工作項目：
  - 文件版本與重建索引流程。
  - 記憶 TTL / forget 一致性驗證。
  - 清理策略（過期、重複、低品質片段）。
- 驗收標準：
  - forget 後查詢不可見；重建後結果一致。

### 7. 成本控制
- 目標：避免 token 成本失控。
- 工作項目：
  - 記錄模型用量與成本估算。
  - 設定每請求/每日預算與告警。
  - 高成本路徑（多代理、長上下文）加上閥值。
- 驗收標準：
  - 可查詢每日成本，超閾值會告警。

## P2（中期優化）

### 8. 多租戶隔離與審計
- 目標：支援企業場景的資料隔離與稽核。
- 工作項目：
  - tenant 邊界（資料、索引、記憶）隔離。
  - 完整審計軌跡（誰在何時做了什麼）。
- 驗收標準：
  - 跨 tenant 無查詢穿透，審計可回放。

### 9. 發版治理（灰度 / 回滾）
- 目標：降低新版本風險。
- 工作項目：
  - CI/CD 增加品質 gate（lint/test/eval/security scan）。
  - 建立灰度比例切換與一鍵回滾。
- 驗收標準：
  - 發版異常可在 10 分鐘內回滾。

### 10. 使用者體驗一致性
- 目標：多代理與工具流結果可理解、可預測。
- 工作項目：
  - 事件文案一致化。
  - 錯誤提示可操作（下一步建議）。
  - 前端顯示路由與工具過程摘要。
- 驗收標準：
  - 使用者可理解「為何選此代理、為何失敗、怎麼重試」。

## 推薦執行順序（兩週）

1. 先做 P0-1 ~ P0-4（安全、觀測、降級）。
2. 並行建立 P1-5（評測回歸）與 P1-6（資料生命週期）。
3. 最後補 P1-7 成本治理，進入常態發版。
