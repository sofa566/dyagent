# 011-health-reminder 變更提案

## 目標

建立「衛教內容提醒」最小可用流程（MVP）：

1. Agent 或人工可新增候選衛教內容（草稿）
2. 後台可人工審核（核准/退回）
3. 核准後可立即發送或建立排程發送到 LINE
4. 保留每次發送紀錄以便稽核

## 背景

- 現有 `010-reminder-schedule` 已有排程任務、模板與 LINE 派送能力。
- 目前缺少「內容治理」層：無法把候選內容與審核流程落地成結構化資料。
- 業務希望保留來源彈性，不採封閉官方白名單，改採「人工核准為硬門檻」。

## 本次要解決的問題

1. 候選衛教內容目前散落在聊天與人工操作，難以追蹤。
2. 缺少核准前禁止發送的後端硬限制。
3. 缺少衛教內容層級的發送紀錄與回查能力。

## 不在本次範圍

1. 自動抓全文與內容摘要評分引擎。
2. 多通道（Email/SMS/推播）發送。
3. 自動化來源品質分級模型（先保留人工審核）。

## 交付原則

1. 先完成最小閉環，再談內容推薦優化。
2. 發送前審核為必要條件，不依賴 prompt 約束。
3. 重用既有 scheduler 基礎能力，減少重複實作。
