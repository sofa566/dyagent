# 排程用法（Executor 與 Payload）

## 1. 先講結論

目前系統的 `executor_type` 是固定清單，新增模板時只能選既有 executor，不需要改程式；
若要新增全新 executor 類型，才需要改後端程式。

目前可用 executor：

1. `http_call`
2. `bash_script`
3. `nodejs_script`
4. `python_script`
5. `renal_reminder_dispatch`
6. `monitoring_backfill`
7. `health_education_dispatch`

---

## 2. 各 Executor 可用 Payload 欄位清單

## 2.1 `http_call`

可用欄位：

- `method`：HTTP 方法，預設 `POST`
- `url`：目標網址（必填）
- `timeout_seconds`：逾時秒數，範圍 2~120
- `headers`：物件
- `json`：物件
- `allow_hosts`：可選，逗號分隔的允許網址前綴

範例：

```json
{
  "method": "POST",
  "url": "https://example.internal/api/report",
  "timeout_seconds": 15,
  "headers": {
    "X-Source": "dyagent"
  },
  "json": {
    "date": "2026-09-21"
  },
  "allow_hosts": "https://example.internal"
}
```

## 2.2 `bash_script`

可用欄位：

- `command`：要執行的 bash 指令（必填）
- `timeout_seconds`：逾時秒數，範圍 2~3600，預設 120
- `workdir`：工作目錄（可選，需在白名單根目錄下）

限制：

- 不可含 `;`, `&&`, `||`, `|`, `>`, `<`, `` ` ``, `$(`
- 指令前綴需在白名單（預設如 `python `、`python3 `、`node `、`npm `、`bash `、`sh `、`./`）

範例：

```json
{
  "command": "python scripts/sync_data.py",
  "timeout_seconds": 120,
  "workdir": "backend"
}
```

## 2.3 `nodejs_script`

可用欄位：

- `file_path`：腳本檔案路徑（必填）
- `args`：參數陣列（可選）
- `timeout_seconds`：逾時秒數，範圍 2~3600，預設 120
- `workdir`：工作目錄（可選）

範例：

```json
{
  "file_path": "scripts/build_report.js",
  "args": ["--mode", "daily"],
  "timeout_seconds": 90,
  "workdir": "backend"
}
```

## 2.4 `python_script`

可用欄位：

- `file_path`：腳本檔案路徑（必填）
- `args`：參數陣列（可選）
- `timeout_seconds`：逾時秒數，範圍 2~3600，預設 120
- `workdir`：工作目錄（可選）

範例：

```json
{
  "file_path": "tests/jobs/daily_report.py",
  "args": ["--date", "2026-09-21"],
  "timeout_seconds": 180,
  "workdir": "backend"
}
```

## 2.5 `renal_reminder_dispatch`

可用欄位：

- `window`：`MORNING` 或 `EVENING`（未填時預設會走 `EVENING`）
- `force`：是否強制執行（布林）

範例：

```json
{
  "window": "MORNING",
  "force": false
}
```

## 2.6 `monitoring_backfill`

可用欄位：

- `lookback_days`：回補天數，範圍 1~14
- `max_scan_rows`：每次掃描上限，預設 5000

範例：

```json
{
  "lookback_days": 2,
  "max_scan_rows": 5000
}
```

## 2.7 `health_education_dispatch`

可用欄位：

- `dispatch_mode`：`fixed` 或 `rotate`
- `audience_rule`：`all`、`diabetic_only`、`non_diabetic_only`
- `content_id`：`fixed` 模式必填
- `cooldown_days`：`rotate` 模式使用，範圍 1~180，預設 30

模式說明：

1. `fixed`：每次固定送同一篇（需要 `content_id`）
2. `rotate`：每次自動挑不同篇，冷卻期內不重複

範例（fixed）：

```json
{
  "dispatch_mode": "fixed",
  "content_id": "7f4cf9b7-b68a-47ec-a485-5fcd9cb96d8d",
  "audience_rule": "all"
}
```

範例（rotate）：

```json
{
  "dispatch_mode": "rotate",
  "audience_rule": "all",
  "cooldown_days": 30
}
```

## 3. 衛教輪替「空轉」定義

`health_education_dispatch` 且 `dispatch_mode=rotate` 時，若本次找不到符合條件文章，
系統會回傳 `reason=no_eligible_content`，這次就算一次空轉。

常見原因：

1. 可用 `approved` 文章不足
2. 全部文章都在冷卻期內
3. 受眾條件限制後無可發送對象

連續空轉達門檻才會告警，門檻由 `.env` 控制：

```env
HEALTH_EDUCATION_ROTATE_EMPTY_ALERT_THRESHOLD=3
```

---

## 4. 建議模板策略

1. 先以 `default_payload` 放通用值（例如 timeout、audience）
2. 再讓任務 `payload` 只填差異值
3. 若是衛教月度推播，優先用 `rotate + cooldown_days=30`
