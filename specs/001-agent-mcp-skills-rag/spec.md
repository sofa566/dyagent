# Feature Specification: Per-Agent MCP/Skills/RAG Config

**Feature Branch**: `001-agent-mcp-skills-rag`
**Created**: 2026-03-15
**Status**: Draft
**Input**: User description: "我記得我提過每個代理者都可以分別加入 MCP 和Skills和RAG，我在畫面上都沒看到，我需要它們在llm-config 頁面上都能設置，並在聊天時都能使用。"

## User Scenarios & Testing (mandatory)

### User Story 1 - 在 LLM 設定頁為單一代理者配置整合 (Priority: P1)

身為代理者的管理者/編輯者，我可以於該代理者的 LLM 設定頁，為此代理者獨立設定：
- MCP（新增/移除/啟用/測試多個 MCP 連線）
- Skills（從可用清單中啟用/停用）
- RAG（選擇檢索來源與基本參數）

Why this priority: 沒有可視化設定，無法落實「每代理者不同能力」的核心價值。

Independent Test: 僅透過進入代理者的 LLM 設定頁，完成配置、測試連線、儲存並再次載入，能看到相同設定被正確保存與呈現。

Acceptance Scenarios:
1. Given 使用者具「更新代理者」權限，When 於 LLM 設定頁新增一個 MCP 連線並點擊「測試」，Then 顯示連線測試結果，儲存後再次進入可見相同設定。
2. Given 使用者具「更新代理者」權限，When 勾選 2 個 Skills 並儲存，Then 再次載入頁面可見 2 個 Skills 處於啟用狀態。
3. Given 使用者具「更新代理者」權限，When 選擇 RAG 的檢索來源與參數並點擊「測試檢索」，Then 能看到範例查詢的預覽結果與成功/失敗提示。

---

### User Story 2 - 聊天時使用該代理者的 MCP/Skills/RAG (Priority: P2)

身為終端使用者，當我選擇某代理者進行聊天時，該代理者會依其個別設定：
- 僅能呼叫被啟用的 MCP 工具；
- 僅能使用被啟用的 Skills；
- 啟用 RAG 時會在回應內使用設定之來源進行檢索與引用。

Why this priority: 確保「每代理者不同能力」在實際互動中生效，而非僅限設定畫面。

Independent Test: 僅透過聊天頁，對同一段話分別使用 A 代理者（有啟用 RAG/MCP）與 B 代理者（未啟用），可觀察行為差異（如 A 會檢索並引用、B 不會）。

Acceptance Scenarios:
1. Given 代理者已啟用某 MCP 工具，When 對話觸發該工具，Then 工具被正確呼叫並影響回覆；若停用該工具再測試，則不會被呼叫。
2. Given 代理者啟用 RAG 並選擇特定來源，When 詢問需要知識檢索的問題，Then 回覆包含檢索結果的引用/摘要；若關閉 RAG 再測試，則不含引用/檢索行為。

---

### User Story 3 - 權限與檢視 (Priority: P3)

身為一般使用者（無更新權限），我可以檢視代理者啟用的能力摘要（唯讀），但無法修改；身為管理者，我可檢視設定變更的審計紀錄（誰在何時做了什麼變更）。

Why this priority: 降低誤操作風險，並提供可追蹤性。

Independent Test: 不更動任何設定即可在代理者頁看到能力摘要與最近變更紀錄。

Acceptance Scenarios:
1. Given 使用者角色為 user，When 進入 LLM 設定頁，Then 僅能查看設定摘要，不提供儲存動作。
2. Given 使用者角色為 admin，When 查詢審計紀錄，Then 能看到每次設定變更的時間、操作者與重點內容。

---

### Edge Cases

- 未啟用任何 MCP/Skills/RAG：聊天應可正常進行，但不使用任何外部工具/檢索。
- MCP 設定有誤（無法連線/認證失敗）：在 LLM 設定頁測試時明確顯示錯誤；聊天時不應嘗試呼叫該 MCP。
- RAG 啟用但無可用來源或查無結果：回覆不應失敗；可顯示「未找到相關內容」的友善表述。
- 權限不足修改：顯示唯讀狀態與禁用儲存按鈕。
- 版本相容：既有代理者在未設定任何整合前，行為與現在相同（不破壞既有流程）。

## Requirements (mandatory)

### Functional Requirements

- FR-001（LLM 設定入口）：在代理者詳情中提供「LLM 設定」頁/區塊，包含 MCP、Skills、RAG 三個可配置分區，並顯示目前啟用狀態摘要。
- FR-002（權限）：具「update_agent」者可編輯並儲存設定；具「read_agent」者可檢視但不可儲存；一般使用者（user）在聊天頁只能使用結果、不可變更設定。
- FR-003（MCP 設定）：可為單一代理者新增/移除 0..N 個 MCP 連線，包含名稱與必要連線參數；提供「測試連線」按鈕並即時回饋結果；每條連線可啟用/停用。
- FR-004（Skills 設定）：顯示可用 Skills 清單，允許逐項勾選啟用/停用，並儲存至該代理者；重新載入後維持相同狀態。
- FR-005（RAG 設定）：可切換啟用/停用 RAG；當啟用時，需可選擇檢索來源（如集合/索引）與基本檢索參數（如上限數量 topK），並提供「測試檢索」以顯示範例結果或錯誤訊息。
- FR-006（儲存與載入）：上述三區設定儲存後，重新進入頁面能正確讀取並呈現；無資料時有合理預設（皆未啟用）。
- FR-007（聊天套用）：聊天時，系統只允許該代理者呼叫被啟用的 MCP/Skills；若未啟用則不得被呼叫；RAG 啟用時會基於所選來源執行檢索並在回覆中引用（或摘要）。
- FR-008（失敗降級）：若某 MCP 測試失敗或在聊天中不可用，系統不得崩潰；應跳過該工具並回覆核心內容（或提供友善提示），同時在內部記錄可觀察訊號。
- FR-009（審計）：對設定的新增/變更/刪除，記錄操作者、時間與重點差異，用於日後稽核。
- FR-010（回溯相容）：對於未設定任何整合的既有代理者，預設行為維持與現在一致，不引入新錯誤或破壞性變更。

澄清結果（用戶決策已確認）：
- FR-011（Skills 來源與邊界）：採「每代理者可自定義新增」策略。每個代理者可在其設定頁新增自定義 Skills，並可啟用/停用；為降低風險，將在審計中記錄新增/變更細節，並提供後續可選的審核流程於未來版本。
- FR-012（RAG 來源顆粒度）：以「集合/索引」為選擇單位。設定頁提供現有集合/索引清單以供選擇，並可設定基本檢索參數（如 topK）。
- FR-013（MCP 安全策略）：預設使用「白名單 + 申請審核」：管理者可直接選擇白名單內端點；若需使用非白名單端點，需提交審核（產生審核請求與審計紀錄）通過後才可使用。

### Key Entities (include if feature involves data)

- Agent：對話與能力承載的主體。
- Agent Integrations（邏輯實體）：代理者的三類整合設定之集合，包含：
  - mcp_config：多條 MCP 連線（id、名稱、連線參數、啟用狀態、最近測試結果摘要）。
  - skills：啟用的 Skills 名稱清單（以及可選排序/權重）。
  - rag_config：是否啟用、來源清單、檢索參數（如 topK ）。

## Success Criteria (mandatory)

### Measurable Outcomes

- SC-001（設定效率）：具備編輯權限的使用者，能在 3 分鐘內完成單一代理者的 MCP/Skills/RAG 設定與測試（以可用連線/來源為前提）。
- SC-002（套用正確性）：在 95% 的測試對話中，系統僅呼叫該代理者被啟用的 MCP/Skills，且 RAG 行為與設定相符（啟用才檢索、來源一致）。
- SC-003（穩定性）：面對不可用的 MCP/RAG 來源時，對話不中斷且提供友善提示；測試過程零崩潰。
- SC-004（可追蹤性）：100% 的設定變更均產生審計紀錄，內容至少包含操作者、時間與變更重點。

### Assumptions

- Skills、RAG 來源與 MCP 清單皆已有一定的全域可用目錄或命名規則；若無，則短期以最小可用集合為主。
- 預設安全立場偏保守：未啟用即不使用；測試失敗即不在對話中嘗試。
- 既有權限模型維持現狀：一般使用者無法修改代理者設定。
