# 使用排程管理

## 1. 這份文件的用途

本文件是「排程管理」頁面的操作手冊，提供以下內容：

1. 功能用途與適用情境
2. 設計方式與系統運作流程
3. 名詞解釋（模板、任務、執行器、payload 等）
4. 逐步操作方式
5. 可直接複製的範例
6. 常見錯誤與排查方式

---

## 2. 功能用途介紹

「排程管理」頁面負責管理兩類資料：

1. **任務模板（Template）**：定義任務類型、必要欄位與預設值。
2. **Crontab 任務（Task）**：定義何時執行，並綁定某個模板來執行。

簡單理解：

- 模板 = 規格書
- 任務 = 依規格書建立的排程實例

此設計讓團隊不必每次新增排程都從零設定，能降低重複與錯誤。

---

## 3. 設計方式（系統如何運作）

### 3.1 架構

1. 後台建立模板（定義 executor 與 payload 規則）
2. 後台建立任務（設定 cron/timezone/template/payload）
3. 任務同步到 RedBeat（Redis）
4. Celery Beat 到點觸發
5. Celery Worker 實際執行任務
6. 寫入 `scheduled_task_runs` 執行紀錄

### 3.2 執行器類型

目前支援：

1. `http_call`
2. `bash_script`
3. `nodejs_script`
4. `python_script`
5. `renal_reminder_dispatch`
6. `monitoring_backfill`

## 4. 名詞解釋

### 4.1 Template Key

模板唯一識別碼，例如：`ops.python.daily-report`。

建議命名格式：`領域.技術.用途`。

### 4.2 executor_type

模板的執行方式。任務建立時會沿用模板的 `executor_type`。

### 4.3 payload

執行任務時帶入的參數，JSON 格式。

### 4.4 payload_schema JSON

用來定義 payload 規格，目前重點是 `required`：

```json
{
  "required": ["file_path"]
}
```

表示 payload 必須包含 `file_path`。

### 4.5 default_payload JSON

模板預設參數，任務若沒填會自動帶入；若任務有填，會覆蓋同名欄位。

```json
{
  "timeout_seconds": 120,
  "args": []
}
```

### 4.6 cron_expression

5 段式 Crontab：`分 時 日 月 週`

範例：

- `0 6 * * *`：每天 06:00
- `*/10 * * * *`：每 10 分鐘

## 5. 欄位填寫與操作方式

## 5.1 先建立模板

進入「排程管理」→「任務模板管理」：

1. 輸入 `Template Key`
2. 輸入模板名稱與說明
3. 選擇 `executor`
4. 填入 `payload_schema JSON`
5. 填入 `default_payload JSON`
6. 勾選是否啟用
7. 按「新增模板」

### 5.2 再建立 Crontab 任務

進入「Crontab 任務管理（Celery）」：

1. 輸入任務名稱
2. 填 `Crontab`
3. 填 `時區`（預設 `Asia/Taipei`）
4. 選擇任務模板
5. 填入任務 payload（可只填差異值）
6. 勾選啟用
7. 按「新增任務」

### 5.3 手動測試

在任務列表按「立即執行」：

1. 系統會建立 run log
2. 若可派送到 Celery，狀態先 queued/running
3. 完成後變成 success 或 failed
4. 可按「最近執行」檢查狀態與時間

## 6. 常見範例（可直接複製）

## 6.1 Python 腳本模板

`payload_schema JSON`

```json
{
  "required": ["file_path"]
}
```

`default_payload JSON`

```json
{
  "timeout_seconds": 120,
  "args": []
}
```

對應任務 `payload`：

```json
{
  "file_path": "tests/jobs/daily_report.py",
  "args": ["--date", "2026-09-16"]
}
```

## 6.2 Node.js 腳本模板

`payload_schema JSON`

```json
{
  "required": ["file_path"]
}
```

`default_payload JSON`

```json
{
  "timeout_seconds": 90,
  "args": []
}
```

對應任務 `payload`：

```json
{
  "file_path": "scripts/build_report.js",
  "args": ["--mode", "daily"]
}
```

## 6.3 Bash 腳本模板

`payload_schema JSON`

```json
{
  "required": ["command"]
}
```

`default_payload JSON`

```json
{
  "timeout_seconds": 60
}
```

對應任務 `payload`：

```json
{
  "command": "python scripts/sync_data.py"
}
```

## 6.4 HTTP Call 模板

`payload_schema JSON`

```json
{
  "required": ["url"]
}
```

`default_payload JSON`

```json
{
  "method": "POST",
  "timeout_seconds": 15,
  "headers": {},
  "json": {}
}
```

對應任務 `payload`：

```json
{
  "url": "https://example.internal/api/report",
  "json": {
    "date": "2026-09-16"
  }
}
```

## 6.5 腎友提醒派送模板（`renal_reminder_dispatch`）

對應任務 `payload`：

```json
{
  "window": "MORNING",
  "force": false
}
```

欄位說明：

1. `window`：提醒時段，支援 `MORNING`（早晨）或 `EVENING`（晚間）。
2. `force`：是否強制補發；`false` 代表依一般規則略過不需提醒對象，`true` 代表即使原本會略過也嘗試發送。

常見使用方式：

1. 每日固定提醒：`{"window":"MORNING","force":false}`
2. 人工補發重跑：`{"window":"MORNING","force":true}`

## 7. 安全與限制（務必閱讀）

### 7.1 腳本路徑白名單

腳本任務的 `workdir`、`file_path` 必須落在白名單路徑內。

環境變數：

- `SCHEDULER_SCRIPT_ALLOWED_ROOTS=src,tests`

### 7.2 Bash 指令限制

`bash_script` 會擋掉高風險運算子（如 `&&`、`|`、`>` 等），且必須符合前綴白名單。

環境變數：

- `SCHEDULER_BASH_ALLOWED_PREFIXES=python ,python3 ,node ,npm ,bash ,sh ,./`

### 7.3 常見失敗原因

1. payload JSON 格式錯誤
2. 缺少 `required` 欄位
3. `file_path` 不存在
4. 路徑不在白名單
5. bash 指令包含不允許運算子
6. 任務執行逾時

---

## 8. 排查建議

1. 先按「立即執行」驗證模板與 payload。
2. 用「最近執行」看 `success/failed` 與時間。
3. failed 時優先檢查 `required`、路徑白名單、timeout。
4. 確認 Celery worker/beat 皆有啟動。
